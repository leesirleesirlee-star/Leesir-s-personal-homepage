## 2. 方案定稿：6 处关键调整（相对最初设想）

| # | 最初设想 | 定稿调整 | 理由 |
|---|---|---|---|
| A1 | 卡片展开后出现画廊 | 点击摄影卡 → FLIP 过渡进**全屏画廊层**（复用现有 modal overlay 架构），卡片动画仅作入场过场 | Cover Flow 需要整视口舞台（两侧封面 + 倒影 + 透视），卡片内部空间不足 |
| A2 | 电脑端滚轮横移 | 滚轮 = **翻页**（deltaY/deltaX 归一化 + 一次手势一档 + ~300ms 冷却），非连续像素滚动 | Cover Flow 是索引驱动；触摸板惯性不节流会一次翻十几张 |
| A3 | 手机端手指滑动 | 保留滑动（位移阈值 >40px 翻页）+ 补充**背景滚动锁定**、下滑关闭/关闭按钮、滑动与点击区分 | 手势闭环，防背景穿透滚动与误触 |
| A4 | （未指定） | 画廊层**强制深色幕布**，独立于全站亮/暗主题 | 倒影在浅色背景不可见（原版即黑底）；契合"暗厅打光"的展厅隐喻 |
| A5 | （未指定） | 流内**不显示照片标题**，仅进度指示（如 `03 / 09`）；大图无信息层（同 D4） | 保持画面纯净，与 D4 口径一致 |
| A6 | 上传作品即上线 | 首期 **9 张单队列**；架构预留"系列/主题"分组扩展（每系列一个 Cover Flow 队列） | 数量少时分组反而稀释翻阅体验 |

## 3. 学习成果：Cover Flow 五要素 → Web 映射

来源文章原理与平台无关；其 SkiaSharp 实现可直接翻译为 CSS 3D，Web 端反而更简单（CSS 原生支持透视与 3D 旋转，无需手写 4×4 矩阵）。

| # | 要素 | 文章做法（MAUI / SkiaSharp） | Web 实现 |
|---|---|---|---|
| 1 | 索引驱动位置算法 | `currentPos` + `step`（相邻间距）+ `slidePadding`（中央与两侧首张间距）；中央 z-index 最高，向两侧递减 | JS 维护 `currentIndex`，`render()` 重算各卡 transform / z-index |
| 2 | 3D 透视旋转 | 4×4 矩阵绕 Y 轴 ±65°，透视距离 800（左 +65° / 右 −65° / 中 0°） | 容器 `perspective: 800~1200px` + 子元素 `rotateY(±65deg)` |
| 3 | 镜像倒影 | 画布下半部绘制 `scaleY(-1)` 翻转图 + 半透明黑罩渐隐 | 伪元素 `::after` + `scaleY(-1)` + `mask-image` 渐变（通用方案，不依赖 `-webkit-box-reflect`，Firefox 一致） |
| 4 | 同步缓动动画 | 全部属性（位移/缩放/旋转/斜切）400ms CubicInOut 同步插值 | `transition: transform 400ms cubic-bezier(0.65,0,0.35,1)` |
| 5 | 响应式参数 | `step = 屏宽×0.12`、`padding = 屏宽×0.15`，随视口重算 | 同思路，JS 读视口宽计算，resize 重渲染 |

**核心洞察**：Cover Flow 是"索引驱动"而非"像素驱动"——任何交互改变的只是当前索引，动画只是索引之间的插值。这是 A2 滚轮翻页方案的原理依据。

## 4. 交互规格

### 4.1 桌面

| 操作 | 行为 |
|---|---|
| 滚轮（deltaY 或 deltaX） | 翻页：一次手势一档，节流冷却 ~300ms；到边界停住（不循环，与原版一致） |
| ← / → 方向键 | 上一张 / 下一张 |
| 点击侧卡 | 将该卡聚焦为当前 |
| ESC / 点击幕布空白 | 关闭画廊，焦点回到摄影卡片 |

### 4.2 移动

| 操作 | 行为 |
|---|---|
| 水平滑动 | 位移阈值 >40px 判定翻页；未过阈值回弹 |
| 点击侧卡 | 聚焦 |
| 点击中央卡 | 看大图（lightbox：原始比例、无信息层、点击关闭） |
| 下滑 / 关闭按钮 | 关闭画廊 |
| 背景页面 | 打开期间 scroll lock，禁止穿透滚动 |

### 4.3 通用

- 边界反馈：第一张向左 / 最后一张向右做轻微位移回弹，不循环。
- 打开画廊时给 `<body>` 加锁类，关闭后恢复滚动位置。

## 5. 视觉规格（默认参数，实施时可微调）

| 参数 | 默认值 | 说明 |
|---|---|---|
| 幕布 | 近黑（如 `#0A0C10` / 96% 不透明），深色磨砂 | 独立于全站主题（A4） |
| perspective | 1000px | 透视距离（文章 800，Web 取 800~1200 区间） |
| 侧卡 rotateY | ±60°（文章 65°，微收敛更耐看） | 左正右负 |
| step / slidePadding | 屏宽×0.12 / 屏宽×0.15 | 沿用文章比例，resize 重算 |
| 侧卡压暗 | `filter: brightness(.55)`，随距离递增 | 突出中央 |
| 倒影 | 高度 ≈40% 原图 + mask 渐隐 | 通用镜像方案（§3-3），深色幕布下效果最佳 |
| 流内卡片比例 | 3:4 竖幅，`object-fit: cover` | D2 统一裁切 |
| 进度指示 | 中央下方 `03 / 09` | 极简，无标题（A5） |
| 入场编排 | 摄影卡放大淡出 → 幕布升起 → 封面依次落位（错峰 ~60ms/张） | 文章未覆盖，需自行设计 |
| 动效时长 | 单次翻页 ~400ms，`cubic-bezier(0.65,0,0.35,1)` | 对齐文章手感 |

## 9. 风险与验收标准

| 风险 | 缓解 | 验收口径 |
|---|---|---|
| Firefox 无 `-webkit-box-reflect` | 伪元素镜像方案（§3-3），全浏览器一致 | Firefox 下倒影正常渐隐 |
| 触摸板惯性导致连翻 | 事件归一化 + 300ms 冷却 | 一次轻扫最多翻 1~2 档 |
| 图片体积拖慢加载 | 三档产物 + 懒加载 + 相邻预载 | 流内首屏图片总重 < 1.5MB |
| 3D 层数过多掉帧 | 视口外卡片 `visibility: hidden` | 手机滑动全程目测流畅（≈55fps+） |
| 亮色主题下突兀 | 画廊层恒定深色幕布 | 双主题下观感一致 |

### 11.1 V5.1 反馈迭代（2026-09-29）：倒影立体化

用户对照原版指出"背景有图片的实时倒影，看起来更立体"。说明：倒影本身已是实时的（位于卡片 3D 变换内部，随每张卡的 rotateY/位移/亮度同步），不足在于**太淡太短且无地面感**（合成强度仅 ~28%，平面镜像贴片）。三项升级：

1. **地面透视**：`.gf-reflection` 以卡片底边为轴 `rotateX(32deg)`，倒影平面铺向观者——近宽远窄的真透视，"躺在 glossy 地板上"而非"贴在墙上"。
2. **强度与长度**：不透明度 0.5→0.62、接触缘 mask 0.55→0.85、长度 34%→52%（移动端 44%），快速渐隐（70% 处透明）。
3. **中央光池**：`.gallery-flow::before` 径向渐变光斑，模拟展厅射灯在地面上的光晕（当前卡恒在中央，光池随之归属）。

资源版本 5.0.0 → 5.1.0；仅 CSS 变更，JS 未动。

### 11.2 V5.2 反馈迭代（2026-09-29）：修复倒影不随侧卡透视收缩

**用户反馈**：翻页时侧卡的倒影没有跟着透视收缩。

**根因**：`.gf-card` 上的 `will-change: transform, opacity`——按 css-will-change 的 grouping 规则，`opacity` 是分组属性，声明 `will-change: opacity` 会强制元素 grouping、把 `transform-style: preserve-3d` 压平。于是倒影的 `rotateX(32°)` 退化为无透视的仿射压扁（无深度、无近宽远窄），仅随卡片 2D 移动。

**修复**（仅 CSS）：
1. 卡片 `opacity` 恒为 1，`will-change` 只留 `transform`（transform 非分组属性，preserve-3d 恢复生效）。
2. 淡入动画移至子元素：`--gf-fade` 自定义属性由 `.gf-card.live` 置 1，`.gf-photo` 用 `opacity: var(--gf-fade)`、`.gf-reflection` 用 `opacity: calc(0.62 * var(--gf-fade))`。
3. 入场错峰通过 `transition-delay: inherit` 传递到子元素（卡片 inline delay 不变，JS 零改动）。
4. reduced-motion 块同步更新。

**效果**：倒影与卡片恢复共面，侧卡转 60° 时倒影水平压缩至约一半宽度并带真实深度收缩；中央卡的倒影也从"仿射压扁"变为真透视梯形。资源版本 → 5.2.0。
